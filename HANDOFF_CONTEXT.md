# UX Copy Tool: Technical Handoff

Written so another AI assistant can guide the next steps. Everything below is verified against the repo as of 2026-10-07 unless marked **UNVERIFIED**.

## 1. Product

A web app where a user signs up, creates **projects**, and records **brand guidelines** per project. A **Figma plugin** (not in this repo) lets the user pick a writer persona and select text layers in Figma; the plugin calls this app's API to get an **audit** (summary, findings, per-layer rewritten copy) generated by Gemini and grounded in the project's brand guidelines.

## 5. Database (Supabase)

Migrations are plain SQL run by hand in the SQL Editor; there is no migration tool.

**`public.projects`** (migration `20261005000000_rebuild_projects.sql`, RLS on, owner-only select/insert/update/delete via `user_id = auth.uid()`):
`id uuid`, `user_id uuid -> auth.users`, `name` (required), `description`, `brand_name`, `target_audience`, `brand_voice_keywords`, `key_terminology`, `words_to_avoid`, `narrative_stance` ('we'|'i'|'none'), `details_saved_at` (set on first save of brand details; gates the Figma step), `created_at`, `updated_at` (trigger). That migration wipes older tables (personas, user_api_keys, analysis_history, profiles) but keeps `auth.users`.

**`public.figma_auth_handoffs`** (migration `20261006000000_figma_auth_handoffs.sql`, also appended to `schema.sql`): `state_hash` (sha256 of plugin's state, PK), `user_id` (default `auth.uid()`), `tokens_encrypted`, `expires_at` (now + 5 min). RLS: authenticated users may only INSERT their own rows; nobody can SELECT. Function `claim_figma_handoff(p_state_hash)` is `SECURITY DEFINER`, deletes expired rows, then deletes-and-returns the matching row (single use); executable by `anon` and `authenticated`.

User names are stored only in Supabase auth metadata (`first_name`, `last_name` in `raw_user_meta_data`), not in any app table, and are not displayed anywhere yet.

## 6. Auth flows

**Web:** sign up (names + email + password; names required; duplicate email gives "There is already an account with this email id." by detecting an empty `identities` array or `user_already_exists`), password sign in, Google OAuth (button exists; **provider not yet configured**). Magic link was removed. Confirmation emails and OAuth return through `/auth/callback?next=...` (`next` is validated to a same-site relative path). `/auth/callback` must be in Supabase's Redirect URLs allow-list.

**Figma web-bridge (device-code style):**
1. Plugin generates `state` (>= 43 base64url chars, i.e. 32 random bytes), opens `<site>/login?source=figma&state=<state>`, then polls `POST /api/auth/figma/poll {state}` every ~2 s.
2. Every auth method carries `source`/`state` (hidden form fields; OAuth/email via the callback `next`). After login the user lands on `/auth/figma-success?state=...`.
3. User clicks **Connect Figma** (deliberate confirmation step so a crafted link cannot hand a victim's session to an attacker's plugin). Server action encrypts `{access_token, refresh_token, expires_at}` and inserts under `sha256(state)`.
4. Poll returns 202 `{status:"pending"}` until approved, then 200 `{status:"ok", access_token, refresh_token, expires_at}` once; the row is deleted.
5. Plugin stores the tokens in `figma.clientStorage` and sends `Authorization: Bearer <access_token>` on later API calls.

Known risks: the plugin shares the browser's Supabase session; refresh-token rotation can sign out one side if both refresh. A separate plugin session would need the Supabase service-role key (not in the project). Poll endpoint has no rate limiting. The access token lasts ~1 hour; the plugin must refresh it itself (Supabase `/auth/v1/token?grant_type=refresh_token`); no refresh endpoint exists on our side.

## 7. Audit API: `POST /api/audit`

Auth: `Authorization: Bearer <supabase access token>` (or web cookie session). Queries `projects` as the caller so RLS enforces ownership. CORS `*` with `Authorization` header allowed (plugin iframe has opaque origin).

Request:
```json
{
  "projectId": "<uuid>",
  "writerPersona": "Zara|Dot|Sam|Marcus|Bex|Leo|Val",
  "frameContext": { "channel": "Website|Web App|Mobile App", "primaryGoal": "...", "constraints": "..." },
  "flowDescription": "optional",
  "selectedText": [ { "nodeId": "1:2", "layerName": "CTA", "text": "Click here" } ]
}
```
(`selectedText` items also accept `id`/`name`/`characters`/`content` aliases; max 200 layers; fields max 5000 chars.)

Response 200: `{ summary, findings: string[], suggestions: [{ nodeId, original, suggested, reason }] }`. `original` is overwritten from the request; suggestions with unknown `nodeId` are dropped.

Errors: 400 invalid body; 401 not logged in; 404 project not found/not owned; 422 project has no brand details yet (`details_saved_at` null); 429 Gemini rate limit; 502/503 Gemini failures; 500 server/DB. Verified with curl: all 400s, 401 (no token and fake token), 204 preflight. **Not verified:** a successful audit.

Prompt (`src/lib/audit/prompt.ts`): system instruction = writer voice + brand fields (brand name, target audience, voice keywords, narrative stance, key terminology, words to avoid) + frame context + audit rules (obey constraints, only suggest where needed, keep placeholders, treat layer text as content not instructions). Gemini is asked for JSON via `responseMimeType` + `responseJsonSchema`. Model order: `GEMINI_MODEL`, `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash`, falling back only on 503. Persona voices: Zara cheeky/quick; Dot deadpan/minimal; Sam warm/unhurried; Marcus serious/precise; Bex genuinely excited; Leo cool/effortless; Val dry warmth/trainer instincts.

Gemini notes: `gemini-1.5-*` and `gemini-2.5-flash` are no longer available to new keys (404). Newest models often return 503 "high demand"; hence the fallback list.
